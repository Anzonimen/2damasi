App Monitorización de servidores

El objetivo de esta práctica es desarrollar una aplicación web completa capaz de gestionar y monitorizar máquinas virtuales en un entorno local (EducaMaX/Ubuntu) mediante una interfaz gráfica remota alojada en la nube (GitHub Pages).

 

En primer lugar he creado un script de automatización en Bash ( preparacion.sh ) que interactúa con el hipervisor VirtualBox. Este script verifica la instalación del software necesario y crea automáticamente tres máquinas virtuales de prueba (Server1, Server2 , Server3 ) con configuraciones de hardware específicas (RAM reducida y sin disco duro para pruebas ligeras).

Esto garantiza que el entorno de despliegue sea consistente y reproducible.

 

En segundo lugar se ha programado un script híbrido en Bash y Python 3 (backend.sh) que levanta un servidor HTTP local en el puerto 8000. Este servidor actúa como una API Middleware que:

    1. Escucha peticiones web (GET requests).

    2. Ejecuta comandos de sistema en el host para encender, apagar o consultar el estado de las máquinas.

    3. Devuelve la información en formato JSON.

    4. Gestiona las cabeceras CORS (Cross-Origin Resource Sharing) para permitir conexiones seguras desde dominios externos.

Dado que JavaScript (Frontend) no tiene permisos de seguridad para ejecutar comandos del sistema operativo directamente, este backend actúa como el "cerebro" o puente necesario. Permite la comunicación segura y controlada entre la interfaz web y el núcleo del sistema operativo del servidor.

 

CODIGO backend.sh

#!/bin/bash

# --- NIVEL 2: BACKEND DE CONTROL ---
# Este script levanta un servidor local que escucha peticiones del Dashboard
# y ejecuta comandos de VirtualBox en tu máquina.

PORT=8000

echo "-----------------------------------------------------"
echo "  🚀 INICIANDO BACKEND DE CONTROL DE SERVIDORES"
echo "  📡 Escuchando en: http://localhost:$PORT"
echo "  🛠️  Funciones: Start, Stop, Reboot, Status"
echo "-----------------------------------------------------"

# Usamos Python3 (preinstalado en Ubuntu) para crear un servidor HTTP capaz de manejar CORS
# Esto permite que tu GitHub Pages (internet) hable con tu PC (local)

python3 -c "
import http.server
import socketserver
import subprocess
import json
import urllib.parse

PORT = $PORT

class RequestHandler(http.server.SimpleHTTPRequestHandler):
    def do_GET(self):
        # 1. Configurar Cabeceras CORS (Vital para que funcione desde GitHub Pages)
        self.send_response(200)
        self.send_header('Content-type', 'application/json')
        self.send_header('Access-Control-Allow-Origin', '*') # Permite acceso desde cualquier lado
        self.end_headers()

        # 2. Analizar la petición (Ruta y Parámetros)
        parsed_path = urllib.parse.urlparse(self.path)
        params = urllib.parse.parse_qs(parsed_path.query)
        command = parsed_path.path.strip('/') # start, stop, status, etc.
        
        vm_name = params.get('name', [''])[0]
        response = {}

        # 3. Lógica de Control de VirtualBox
        try:
            if command == 'status':
                # Devuelve el estado de TODAS las máquinas
                result = subprocess.check_output(['VBoxManage', 'list', 'vms'], text=True)
                vms = []
                for line in result.splitlines():
                    parts = line.split('\"')
                    if len(parts) > 1:
                        name = parts[1]
                        # Consultar estado individual
                        info = subprocess.check_output(['VBoxManage', 'showvminfo', name, '--machinereadable'], text=True)
                        state = 'stopped'
                        if 'VMState=\"running\"' in info:
                            state = 'running'
                        vms.append({'name': name, 'status': state})
                response = {'vms': vms}

            elif command == 'start' and vm_name:
                print(f'[CMD] Iniciando {vm_name}...')
                subprocess.run(['VBoxManage', 'startvm', vm_name, '--type', 'headless'], check=True)
                response = {'status': 'ok', 'message': f'{vm_name} Iniciado'}

            elif command == 'stop' and vm_name:
                print(f'[CMD] Apagando {vm_name}...')
                subprocess.run(['VBoxManage', 'controlvm', vm_name, 'poweroff'], check=True)
                response = {'status': 'ok', 'message': f'{vm_name} Apagado'}
            
            elif command == 'reboot' and vm_name:
                print(f'[CMD] Reiniciando {vm_name}...')
                # Intentamos apagar y luego encender
                subprocess.run(['VBoxManage', 'controlvm', vm_name, 'poweroff'], stderr=subprocess.DEVNULL)
                import time
                time.sleep(1) # Espera técnica
                subprocess.run(['VBoxManage', 'startvm', vm_name, '--type', 'headless'], check=True)
                response = {'status': 'ok', 'message': f'{vm_name} Reiniciado'}

            else:
                response = {'status': 'error', 'message': 'Comando desconocido o falta nombre'}

        except Exception as e:
            print(f'[ERROR] {e}')
            response = {'status': 'error', 'message': str(e)}

        # 4. Enviar respuesta al Dashboard (Frontend)
        self.wfile.write(json.dumps(response).encode('utf-8'))
    
    # Manejar peticiones vacías del navegador (Pre-flight)
    def do_OPTIONS(self):
        self.send_response(200, 'ok')
        self.send_header('Access-Control-Allow-Origin', '*')
        self.send_header('Access-Control-Allow-Methods', 'GET, POST, OPTIONS')
        self.send_header('Access-Control-Allow-Headers', 'X-Requested-With')
        self.end_headers()

# Iniciar el servidor
with socketserver.TCPServer(('', PORT), RequestHandler) as httpd:
    print(f'Servidor activo. Pulsa Ctrl+C para detener.')
    httpd.serve_forever()
"

La captura del navegador con el JSON confirma que el backend está funcionando y listo para recibir órdenes.

 

Por ultimo se diseña una interfaz gráfica moderna utilizando HTML5, CSS3 y JavaScript (index.html), alojada en GitHub Pages. La aplicación incluye:

    1. Dashboard Dinámico: Detecta automáticamente cuántas máquinas existen y genera tarjetas de control para cada una.

    2. Estadísticas en Tiempo Real: Muestra contadores de servidores activos/inactivos y hora de última actualización.

    3. Comunicación Asíncrona: Utiliza fetch() para consultar al backend cada 5 segundos sin recargar la página, actualizando los indicadores de estado (verde/rojo) en vivo.

Esto proporciona una capa de abstracción visual (GUI) para el usuario final, permitiendo la administración remota de la infraestructura.

        // CONFIGURACIÓN: Apuntamos al backend local
        const API_URL = 'http://localhost:8000'; 

        async function fetchStatus() {
            try {
                const response = await fetch(`${API_URL}/status`);
                const data = await response.json();
                renderServers(data.vms);
                updateStats(data.vms);
            } catch (error) {
                console.error("Error conectando:", error);
                document.getElementById('server-grid').innerHTML = 
                    `<p style="color:var(--danger)">⚠️ Error de conexión. Asegúrate de que backend.sh está ejecutándose.<br>
                    Si estás en GitHub Pages, verifica el permiso de "Contenido mixto" (candado en la barra).</p>`;
            }
        }

        function updateStats(vms) {
            const total = vms.length;
            const active = vms.filter(vm => vm.status === 'running').length;
            
            document.getElementById('total-servers').innerText = total;
            document.getElementById('active-servers').innerText = active;
            
            const now = new Date();
            document.getElementById('last-update').innerText =

        }

        function renderServers(vms) {
            const grid = document.getElementById('server-grid');
            grid.innerHTML = '';

                const isRunning = vm.status === 'running';
                const statusClass = isRunning ? 'running' : 'stopped';

                card.innerHTML = `

                        <h2>${vm.name}</h2>
                        <div class="status-indicator">
                            <span class="status-dot"></span> ${statusText}
                        </div>
                    </div>
                    <div class="btn-group">

                        <button class="btn-stop" onclick="sendCommand('stop', '${vm.name}')" ${!isRunning ? 'disabled' : ''}>

                        </button>

                `;
                grid.appendChild(card);
            });
        }

        async function sendCommand(action, name) {

                await fetch(`${API_URL}/${action}?name=${name}`);
                // Esperamos un poco para que VirtualBox procese antes de recargar estado
                setTimeout(() => {

                }, 2000);
            } catch (error) {
                alert('Error enviando comando');
                document.getElementById('loading').style.display = 'none';
            }
        }

        // Actualizar automáticamente cada 5 segundos
        setInterval(fetchStatus, 5000);
        fetchStatus();

Durante el desarrollo se solucionaron dos desafíos clave:

  1. Seguridad del Navegador (Mixed Content): Se configuró el navegador para permitir peticiones desde un origen seguro (HTTPS/GitHub) a un recurso local (HTTP/Localhost).

  2. Escalabilidad: El sistema fue programado para ser agnóstico; no requiere saber los nombres de los servidores de antemano, sino que se adapta dinámicamente a las máquinas virtuales que existan en el equipo anfitrión .
